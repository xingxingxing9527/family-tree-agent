# 父母关系自动补全：管理员指南

父母关系自动补全用于减少普通夫妻家庭中的重复录入。它只会依据已经保存且仍有效的婚姻事实提出建议；建议必须经过预览和管理员确认才会写入，不会静默创建人物或关系。

## 在人物中心录入

打开人物详情后，在“家庭关系”中直接维护该人物的父亲、母亲、配偶和子女，无需再次选择当前人物。录入子女时：

- 选择“当前人物作为父亲”或“当前人物作为母亲”，再勾选一名或多名子女；需要新人物时可使用“快速新建子女”。
- 点击“生成子女关系预览”。普通夫妻且候选唯一时，预览会同时列出一条“人工录入”和一条“系统自动补全”。
- “人工录入”表示管理员明确选择的关系；“系统自动补全”表示依据已确认婚姻提出的另一位父母。自动项旁会显示来源婚姻的双方姓名、状态和日期范围，不显示内部记录编号。
- 自动项默认选中，但可在确认前取消。取消后只保存人工录入的关系，婚姻事实不受影响。

一次勾选多个子女时，每个子女都会分别规划。统一预览仍是一次操作；确认后写入同一操作组，任一阻断错误都会阻止整组提交。

## 歧义、无候选和角色占用

有离婚或再婚记录时，系统会比较孩子出生日期与各段婚姻区间。只有一段区间能匹配时，才会默认建议该配偶。日期缺失、历法不同、精度不足或多个候选均无法排除时，预览会列出候选及婚姻依据，管理员必须为该子女选择一人，或选择“暂时跳过”。跳过只保留明确关系，之后可以再次补录。

“没有可用候选”表示当前人物没有可用于补全的已确认婚姻配偶。管理员仍可保存合法的明确关系，也可以先录入婚姻，再重新发起关系录入。系统不会为此创建占位人物。

如果孩子的互补父母角色已经被另一人占用，自动项会显示冲突并且不会覆盖原关系；不冲突的明确关系仍可继续预览。先核实并更正或移除错误关系，再重新补全。

## 修正、移除、撤销和历史批修复

关系行上的来源 badge 用于区分“人工录入”和“系统自动补全”。来源只解释该关系如何产生；婚姻后来变更为离婚，不会自动删除已经确认的亲子关系。

- “更正”会把移除旧关系和加入替代关系放进同一预览；确认前不会改库。
- “移除”只移除所选亲子关系，不会连带删除来源婚姻。
- 如需恢复整次误操作，在“操作历史”中对相应操作组执行撤销。若后续数据已变化，系统会阻止不安全的撤销并要求重新核对。

对于上线前已有的“仅录入一位父母”数据，使用“检查未完整父母关系”。扫描本身只读：可安全补全的项目默认选中；歧义、无候选和冲突只显示问题。管理员选择项目并进入统一预览、再次确认后才会批量写入。修复完成后，刷新人物详情与家谱树，相关家庭不再显示为单亲家庭。

## 对话录入的确认边界

对话中的自动补全只读取本次草稿生成前已经持久化的婚姻。若同一份对话草稿同时包含“新增婚姻”和“新增亲子关系”，新婚姻不会立即作为亲子补全依据：先预览并确认婚姻，待婚姻持久化后，再发起亲子关系指令并进行第二次预览确认。两次确认都不可省略。

## 首版范围

首版只持久化生父、生母和生物学子女。收养、养父母、继父母、监护人及其他复杂亲属类型尚不支持；遇到这些情况时应取消、跳过或移除不适用的自动生物学关系，保留真实婚姻事实，并在资料备注中说明，不能把复杂关系误录为生物学父母。
