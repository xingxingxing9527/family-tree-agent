# 巩义地区亲属称谓分层设计

## 目标

在不改变现有亲属路径计算方式的前提下，为家谱增加“正式称谓 + 河南郑州巩义地区称谓”两层称谓体系。家谱树优先显示更自然的巩义称呼，人物详情保留正式称谓和关系解释，对话智能体用口语化方式回答，同时让系统继续依据稳定的结构化关系理解人物关系。

首版固定使用 `zh-CN-henan-gongyi`，覆盖常用四代亲属。暂不提供地区切换、管理员自定义词表或大模型临时生成地方称谓。

## 核心原则

- 关系事实和关系路径是唯一计算依据；任何中文称谓都不是关系身份。
- 正式称谓库与地区词表分开维护，地区词表只覆盖有差异且已经确认的称呼。
- 页面不得从正式称谓字符串反向猜测地区称谓。
- 地区词表没有命中时必须降级为正式称谓；正式规则没有命中时使用可解释的组合关系。
- 数据冲突、路径缺失或长幼不明时不得猜测。
- `primaryTerm` 和 `reverseTerm` 作为兼容字段继续表示正式称谓，不静默改成地区称谓。

## 三层关系表达

每个已计算关系同时保留：

| 层级 | 示例 | 用途 |
|---|---|---|
| 关系路径 | 祖母的姐姐 | 解释推导过程、排查录入问题 |
| 正式称谓 | 姨祖母 | 系统通用表达、跨地区理解 |
| 地区称谓 | 姨奶奶 | 巩义地区页面主称谓和自然语言回答 |

计算顺序固定为：

> 亲属事实 → 关系路径签名 → 正式规则 → 巩义词表覆盖 → 展示称谓

## 规则目录架构

### 正式称谓目录

现有 `app/resources/kinship-rules/mandarin-v1.json` 继续保存：

- 稳定规则编号 `rule.id`；
- 关系路径模式 `pattern`；
- 正式正向称谓 `forward`；
- 正式反向称谓 `reverse` 或 `reverseByViewpointGender`。

首版在该目录中补齐常用四代范围内缺失的精确路径，但不把巩义地区词语写入此文件。

### 巩义地区覆盖目录

新增 `app/resources/kinship-locales/zh-CN-henan-gongyi-v1.json`：

```json
{
  "locale": "zh-CN-henan-gongyi",
  "version": "zh-CN-henan-gongyi-v1",
  "formalCatalogVersion": "mandarin-v1",
  "terms": [
    { "ruleId": "paternal-grandmothers-older-sister", "term": "姨奶奶" }
  ]
}
```

地区目录只通过正式规则编号关联，不复制路径模式。加载时必须拒绝：

- 重复的 `ruleId`；
- 空白称谓；
- 正式目录中不存在的规则编号；
- 与当前正式目录版本不匹配的 `formalCatalogVersion`。

地区词表是稀疏覆盖表。正式称谓本身已经自然、或尚未由用户确认地方说法时，不需要添加重复条目。

## 领域输出模型

每一个主路径和备选路径都输出：

```ts
interface KinshipDisplayLabel {
  formalTerm: string | null;
  regionalTerm: string | null;
  displayTerm: string | null;
  pathDescription: string | null;
  formalRuleId: string | null;
  locale: "zh-CN-henan-gongyi";
  regionalRuleVersion: "zh-CN-henan-gongyi-v1";
}
```

`RelationshipResult` 和 `RelationshipAlternative` 吸收这些字段，同时保留现有字段：

- `primaryTerm` 始终等于 `formalTerm`，用于兼容现有调用；
- `reverseTerm` 继续表示正式反向称谓；
- `ruleVersion` 继续表示正式目录版本；
- `displayTerm` 等于 `regionalTerm ?? formalTerm`；
- 当地区词和正式词完全相同时，将 `regionalTerm` 规范化为 `null`，避免界面重复展示；
- 发生关系冲突或没有可用路径时，三个称谓字段均为 `null`。

批量家谱投影使用新的 `calculatePrimaryLabels(viewpointId, targetIds)`，一次返回结构化标签。现有 `calculatePrimaryTerms` 暂时保留，并继续返回正式称谓。

## 可读关系路径

`pathDescription` 不包含人物 ID、关系 ID 或调试符号，而是给用户阅读的关系说明。

对于从父母向上延伸的路径，先使用最长的连续直系祖先段作为锚点，再解释剩余路径：

- `father → mother → olderSister`：`祖母的姐姐`；
- `father → mother → brother → daughter`：`祖母的侄女`；
- `father → mother → sister → daughter → husband`：`祖母的外甥女的丈夫`。

对于配偶侧路径，保留配偶作为语法锚点，例如“丈夫的表妹”。没有可用精确片段时使用现有中性组合逻辑，但不得退化为内部 ID。

## 首版已确认的巩义覆盖

首版必须包含以下规则族；同一关系的长、幼和未知长幼变体使用相同地区称谓：

| 关系路径 | 正式称谓 | 巩义称谓 |
|---|---|---|
| 祖母的姐姐或妹妹 | 姨祖母 | 姨奶奶 |
| 祖母的哥哥或弟弟 | 舅祖父 | 舅爷 |
| 祖母的兄弟的女儿 | 父亲的表姐妹 | 表姑 |
| 祖母的姐妹的女儿的丈夫 | 父亲的表姐妹之夫 | 表姑父 |

其他现有称谓如果地区表达与正式表达相同，直接由正式称谓降级显示。新增其他巩义词语必须先由用户确认，再进入该覆盖目录。

## 常用四代覆盖边界

正式称谓和组合关系需要覆盖：

- 父母、祖父母、外祖父母、曾祖父母和外曾祖父母；
- 祖父母的兄弟姐妹及配偶；
- 父母的兄弟姐妹、堂表兄弟姐妹及其配偶；
- 亲兄弟姐妹、同父异母或同母异父兄弟姐妹、堂表兄弟姐妹及其配偶；
- 子女及配偶、孙辈及配偶、曾孙辈；
- 当前配偶、离异配偶和再婚记录中能够从已确认事实计算出的关系。

超出该范围的关系仍可遍历。未命中地区词表时显示正式精确称谓或正式组合关系，不扩大首版地区词表。

## 降级、长幼和冲突规则

称谓选择顺序为：

1. 精确巩义称谓；
2. 精确正式称谓；
3. 正式组合关系；
4. 无可靠路径时显示“关系待确认”的界面状态。

长幼规则沿用现有出生日期区间判断：

- 年份不同且区间不重叠时可以判断；
- 同年但月份或日期不足、日期区间重叠、农历尚未可靠换算或出生资料缺失时，使用中性称谓；
- 不得根据人物编号、录入顺序或树上位置判断长幼。

同一人物存在多条有效路径时，继续使用现有主路径排序；其他路径作为备选关系保留。任何候选路径存在影响称谓的冲突时，不生成地区称谓，并展示现有冲突说明。

## 离婚与再婚

- 离婚后不把前配偶当作当前配偶；前配偶继续使用正式的历史婚姻表达。
- 首版不为前配偶衍生的姻亲关系增加巩义地区覆盖，除非以后单独确认。
- 再婚记录分别保存，不相互覆盖。
- 子女称谓只依据已确认的父母—子女事实，不依据父母当前配偶推断。
- 婚姻状态变化不改变已经存在的血缘称谓。

## 家谱树和人物详情

家谱树人物卡显示：

```text
李小梅
姨奶奶
正式关系：姨祖母
```

- `displayTerm` 作为醒目的主称谓；
- 仅当 `regionalTerm` 存在且与正式称谓不同时显示“正式关系”；
- `pathDescription` 不放在人物卡上，避免卡片过高；
- 标签增加一行后同步调整节点高度和 ELK 布局尺寸，不能重新引入人物卡遮挡。

点击人物后的右侧详情显示：

```text
你对该人物的称呼：姨奶奶
正式称谓：姨祖母
关系说明：祖母的姐姐
地区规则：河南郑州巩义
```

没有选择当前视角时不显示该关系区域。切换视角后，树和抽屉都使用新视角重新计算。

## 对话智能体

结构化关系查询必须优先使用计算结果，不由模型发明称谓。直接询问关系或称呼时回答：

> 按巩义的常用叫法，李小梅是你的“姨奶奶”。正式称谓是“姨祖母”，她是你祖母的姐姐。

如果没有地区覆盖，则使用正式称谓，并说明关系路径。对于包含多个意图的复杂问题，模型仍可组织答案，但工具结果中的 `displayTerm`、`formalTerm` 和 `pathDescription` 是唯一可信称谓来源。

问答页面同时展示结构化的正式称谓和关系说明，避免自然语言摘要遗漏关键信息。

## 验收标准

- 四个已确认案例分别得到 `姨奶奶 / 姨祖母`、`舅爷 / 舅祖父`、`表姑 / 父亲的表姐妹`、`表姑父 / 父亲的表姐妹之夫`。
- 地区目录缺少条目时，`regionalTerm` 为 `null`，`displayTerm` 等于正式称谓。
- 关系冲突时不会输出任何正式或地区展示称谓。
- 长幼资料不足时不生成带“伯、叔、哥、弟、姐、妹”含义的错误地区称谓。
- 家谱批量标签与单人关系查询结果完全一致。
- 切换视角后，树卡、人物抽屉和问答都使用新视角。
- 地区称谓和正式称谓相同时只显示一行。
- 离婚、再婚和同父异母或同母异父关系继续通过现有回归测试。
- 100–1000 人家谱继续使用现有批量路径查询，不为每个树节点增加重复后端查询。

## 非目标

- 不增加数据库字段或迁移。
- 不允许用户编辑或导入地区称谓词表。
- 不根据用户 IP、地址或姓名自动选择地区。
- 不使用大模型补全词表缺口。
- 不在本次加入收养、继亲、监护等新的关系类型。
- 不重写现有路径搜索、冲突检测、树视图范围或家庭联合布局算法。
