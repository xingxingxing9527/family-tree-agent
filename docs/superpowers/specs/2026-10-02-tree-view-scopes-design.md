# 家谱视图范围重构设计

## 目标

将家谱树目前含义重叠、名称偏专业的“全谱、支系、祖先、后代”重构为四种用户目的明确的视图：

1. 全谱
2. 本家支系
3. 核心亲属
4. 子孙后代

四种范围由后端统一计算，网页只负责选择与展示。关系问答后续可以复用同一套范围定义，避免图谱和智能体对同一概念给出不同结果。

本次不新增数据库字段，不按姓名中的姓氏推测家族归属，不引入复杂收养、继亲等首版范围之外的关系类型。

## 页面概念

页面保留两个彼此独立的选择：

- **当前视角**：决定其他人物相对于谁显示称谓。
- **围绕谁查看**：原“视图中心”，决定本家支系、核心亲属和子孙后代从谁开始计算。

“全谱”不依赖“围绕谁查看”；其他三个视图必须有中心人物。切换视图不会改变当前称谓视角。

页签固定按范围从广到窄排列：

> 全谱｜本家支系｜核心亲属｜子孙后代

页签下方显示动态范围说明和可见人物数量，并统一注明“结果基于当前已确认关系”。例如：

> 正在显示闫明的父母、祖父母、兄弟姐妹、配偶和子女，共 12 人。结果基于当前已确认关系。

## 四种视图定义

### 全谱

显示当前谱册中所有已录入人物、婚姻、共同父母、单亲家庭和亲子关系。它延续现有全谱行为，不受中心人物限制。

### 本家支系

以管理员明确维护的支系归属为依据：

- 默认使用中心人物标记为主要支系的活动支系。
- 人物属于多个支系时提供支系选择框，默认选中主要支系。
- 多个支系同时标记为主要支系时要求用户选择，并提示管理员修正归属。
- 没有主要支系时显示空状态和“前往设置本家支系”入口。
- 不根据显示姓名或姓氏自动判断支系。

范围包含该支系全部已确认成员，包括 `blood`、`married_in` 和 `associated` 三种归属角色。对血缘成员补充其当前配偶；已离婚前配偶只有在双方拥有共同子女时才补充，以保留子女家庭的完整结构。

### 核心亲属

以中心人物为原点，范围严格限定为：

- 中心人物本人；
- 父母；
- 父系和母系祖父母；
- 与中心人物至少共享一位父母的全部兄弟姐妹，包括亲兄弟姐妹、同父异母和同母异父兄弟姐妹；
- 全部子女；
- 当前配偶；
- 与中心人物拥有共同子女的已离婚前配偶。

不继续展开曾祖父母、孙辈、兄弟姐妹的配偶、兄弟姐妹的子女、配偶的父母或配偶与其他关系所生的子女。

兄弟姐妹的类型可以通过现有关系数据计算；若界面展示类型，则使用“亲兄弟姐妹”“同父异母”或“同母异父”等明确文案，不改变底层亲子事实。

### 子孙后代

从中心人物沿已确认亲子关系持续向下遍历，包含：

- 中心人物本人；
- 所有层级的子女、孙辈、曾孙辈及更下代后代；
- 每位后代的当前配偶；
- 与该后代拥有共同子女的已离婚前配偶。

不包含中心人物的父母、祖父母和兄弟姐妹。配偶与其他关系所生、且与中心人物不存在后代链路的孩子不会被带入。

## 共同子女与婚姻规则

“拥有共同子女”定义为：存在同一个人物，且该人物对婚姻双方都具有活动的已确认亲子事实。判断不依赖亲子事实是人工录入还是配偶自动补全，也不要求亲子事实必须由该婚姻记录推导。

婚姻展示规则为：

- 当前婚姻中的配偶纳入对应范围；
- 已离婚前配偶仅在双方拥有共同子女时纳入核心亲属、子孙后代和支系补充范围；
- 纳入的离婚关系继续显示“已离婚”状态和已有起止日期；
- 没有共同子女的前配偶仍保留在全谱和人物婚姻历史中。

## 后端架构

新增独立的范围解析单元 `TreeScopeResolver`，输入人物、亲子事实、婚姻和支系归属，输出当前视图允许出现的人物 ID、关系 ID 及范围元信息。范围解析不负责坐标布局，也不修改事实。

现有家谱投影继续负责将解析结果转换为人物节点、家庭联合节点和关系线：

1. `TreeScopeResolver` 按视图计算人物和允许的关系集合。
2. `TreeProjectionService` 只使用该集合生成拓扑，不因某个已选人物的其他关系而额外拉入范围外人物。
3. 现有 ELK 布局继续为最终拓扑计算坐标。
4. 现有称谓解析继续以“当前视角”为依据为可见人物生成称谓。

范围遍历使用已访问集合，时间复杂度保持为人物和关系数量的线性级别，并阻止错误环路造成无限展开。100 至 1000 人仍沿用现有内存投影和缓存策略；关系或支系写入后使相关投影失效并重新生成。

## API 与类型调整

`TreeViewDto` 调整为：

```ts
type TreeViewDto = "full" | "lineage" | "core" | "descendants";
```

`projectTree` 输入继续接受 `view`、`subjectId`、`viewpointId` 和 `collapseDepth`，并为本家支系增加可选的 `lineageId`：

- `full`：`subjectId` 和 `lineageId` 均可省略。
- `lineage`：需要 `subjectId` 与经过页面选择的 `lineageId`。
- `core`、`descendants`：需要 `subjectId`。

页面从已有 `WorkspaceSnapshotDto.lineages` 读取中心人物的支系归属和可切换支系，不增加新的读取接口。后端仍会验证人物、支系和归属都属于当前工作区，不能仅信任前端选择。

旧的 `branch` 和 `ancestors` 视图不再出现在新契约中。当前产品没有公开兼容承诺或持久化视图 URL，因此直接更新内部调用和测试，不增加长期别名。

## 拓扑边界

范围解析后，拓扑必须遵守以下约束：

- 任何人物节点都必须属于解析得到的人物集合。
- 家庭联合节点只连接范围内需要展示的关系，不能以保持完整联合为由拉入范围外人物。
- 核心亲属中的兄弟姐妹可以通过范围内父母连接，但不会因此展示他们的配偶和子女。
- 子孙后代中的配偶只作为对应后代的配偶出现，其无关子女和原生家庭不会展开。
- 支系补充的配偶不自动带入其父母、兄弟姐妹或其他关系所生子女。
- 被纳入的当前或离婚婚姻继续使用现有婚姻联合节点；亲子关系继续使用共同父母或单亲联合节点。

## 页面状态与错误处理

- 未选择中心人物时，“本家支系、核心亲属、子孙后代”显示选择引导，不发起无效查询。
- 支系缺失或主要支系冲突使用可操作的空状态，不回退到姓氏猜测，也不把它当作系统崩溃。
- 父母、祖父母或其他关系尚未录入时只显示已知人物，并保留“基于当前已确认关系”的说明。
- 查询失败继续使用现有错误提示和重试路径。
- 切换视图后，如果原选中的人物或关系不在新投影中，关闭右侧抽屉；仍在范围内时保留有效选择。
- 人物节点、婚姻节点和亲子关系线继续复用现有查看、编辑、预览、确认和撤销流程。

## 验收与测试

领域测试至少覆盖：

- 全谱人物和联合范围保持不变；
- 核心亲属包含双系祖父母、亲兄弟姐妹、同父异母和同母异父兄弟姐妹；
- 核心亲属不包含曾祖父母、孙辈、兄弟姐妹的配偶和子女；
- 当前配偶始终纳入，前配偶只在有共同子女时纳入；
- 本家支系只依据活动支系归属，并处理单一主要支系、多个可选支系、多个主要支系冲突和未设置支系；
- 子孙后代遍历全部代际，纳入必要配偶，不带入配偶的无关孩子或原生家庭；
- 循环或重复关系不会无限遍历或产生重复节点。

界面与浏览器测试至少覆盖：

- 页签名称和顺序为“全谱、本家支系、核心亲属、子孙后代”；
- “视图中心”更名为“围绕谁查看”；
- 动态范围说明、人物数量和数据边界提示正确；
- 支系选择、缺失引导和主要支系冲突提示可操作；
- 切换视图后选中状态与右侧抽屉正确保留或关闭；
- 四种视图中人物、婚姻和亲子关系仍可正常点击和编辑；
- 1000 人性能门禁和现有网页完整回归继续通过。

## 非目标

- 不根据姓名自动拆分姓氏或推断支系。
- 不在本次引入自定义层数、自由组合条件或高级筛选器。
- 不新增收养、继亲、监护等关系类型。
- 不改变现有称谓算法、事实写入确认、冲突校验、审计或撤销机制。
